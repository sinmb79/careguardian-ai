# Task 15 — 도달 가능한 기기 내 생활 알림

## 결함과 목표

실제 서명 릴리스 QA에서 오늘 작업 입력 폼에 알림 날짜가 없어 `dueDate`가 저장되지 않았고, 따라서 기존 기기 내 알림 동기화가 실행될 수 없었다. 작업 생성부터 저장·동기화까지 날짜 기반 알림을 실제로 도달 가능하게 만든다.

## 요구사항

1. 오늘 작업 폼에만 선택 입력 `알림 날짜 (선택, 오전 9시)`를 표시한다. 자리표시는 `YYYY-MM-DD`이며 접근성 레이블과 설명을 제공한다. 목록 입력 폼에는 날짜 입력을 추가하지 않는다.
2. `addWorkspaceTask`는 선택 날짜 인자를 받고 앞뒤 공백을 제거한다. 빈 값은 `dueDate`를 저장하지 않는다. 비어있지 않은 값은 정확한 그레고리력 `YYYY-MM-DD`만 허용한다. 형식 오류, 존재하지 않는 날짜, 기기 현지 시각 오전 9시 기준 과거 날짜는 명확한 한국어 오류로 실패하고 입력 워크스페이스를 바꾸지 않는다.
3. 시간 비교는 주입 가능한 의존성의 고정 `now`를 사용하고 기기 현지 시간대를 따른다. UTC 문자열 파싱이나 테스트 실행 환경 시간대에 의존하지 않는다.
4. 성공한 작업은 `dueDate`를 저장하고 오늘 목록에 표시한다. 폼은 성공 후 제목과 날짜만 비우며, 오류 시 제목과 날짜 모두 보존한다.
5. 저장·동기화는 미래의 유효한 열린 작업만 기존의 일반·비공개 본문과 `taskId`로 예약한다. 과거 트리거는 네이티브 예약 시도 전에 제외한다. 권한 흐름은 변경하지 않는다.
6. 의료 문구, 클라우드 AI, 계정, 분석 기능을 추가하지 않는다.
7. 단위·UI 소스·알림 과거/미래·상태 저장 통합 테스트를 갱신하고 UTF-8 한국어를 그대로 확인한다.

## 검증

- 대상 Vitest 테스트를 먼저 RED로 확인한 뒤 구현한다.
- `npm run verify`, `npm run mobile:typecheck`, `npm run diff-check`를 실행한다.
- 제품 구현 커밋과 SDD 보고 커밋을 분리한다.
