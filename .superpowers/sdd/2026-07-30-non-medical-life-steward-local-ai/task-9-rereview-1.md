## Important

### I-07. 분할 문자열로 계산한 네트워크 API와 URL이 비의료ㆍ로컬 전용 게이트를 우회합니다

`globalThis["fet" + "ch"]`와 `"https:" + "//evil.example"`처럼 API 이름과 URL을 각각 분할해 실제 원격 전송 코드를 추가해도 `release:policy-check`가 통과했습니다. 현재 AST 검사는 일부 계산 표현식을 정적으로 접지 못해, 원시 `fetch` 또는 완성된 URL 리터럴이 없는 변이를 놓칩니다.

**영향:** 로컬 전용이라고 선언한 릴리스에 임의 원격 전송 경로가 들어가도 자동 게이트가 승인할 수 있습니다.

**필수 조치:** 문자열 리터럴의 이항 결합, 계산 속성 접근, 템플릿 표현식을 정적으로 평가해 네트워크 API와 URL을 검출하십시오. 같은 우회 변이를 자동 음성 테스트로 고정하고, 평가할 수 없는 동적 호출은 실패 폐쇄형으로 처리하십시오.

### I-08. 런타임 모델 레지스트리 동결을 무력화해도 모델ㆍ정책 게이트가 통과합니다

`deepFreeze`를 no-op으로 바꾸고 승인되지 않은 다운로드 URL을 분할 문자열로 구성하는 변이에서 `release:model-check`와 `release:policy-check`가 모두 통과했습니다. 구조화된 JSON 값 검증은 강화됐지만, 내보낸 런타임 레지스트리가 실제로 재귀 동결되는지는 게이트가 보장하지 않습니다.

**영향:** 설치 가능 모델 목록, 해시 또는 다운로드 경로가 런타임에서 변조돼 공급망 허용 목록을 우회할 수 있습니다.

**필수 조치:** 내보낸 레지스트리와 모든 중첩 객체ㆍ배열이 `Object.isFrozen`을 만족하는지 실행 가능한 계약 테스트로 검증하십시오. `deepFreeze` 구현을 제거하거나 no-op으로 바꾸는 변이가 반드시 실패하도록 하고, 분할 URL도 I-07의 정적 평가로 차단하십시오.

### I-09. 손상된 웹 저장 레코드는 사용자의 전체 삭제 요청 뒤에도 보존됩니다

`clearWorkspace()`는 현재 IndexedDB 레코드가 `invalid`이면 `{ kind: "invalid" }`를 반환하고 기존 raw 레코드를 그대로 둡니다. 현재 테스트도 이 보존 동작을 기대하므로, 손상되거나 이전 형식인 개인 데이터는 사용자가 명시적으로 전체 삭제를 눌러도 톰스톤으로 대체되지 않습니다.

**영향:** 삭제 요청 뒤에도 복구 가능한 원시 개인 데이터가 IndexedDB에 남아 전체 삭제 보장과 충돌합니다.

**필수 조치:** 명시적 전체 삭제는 유효성이나 revision과 무관하게 앱 소유 raw 레코드를 제거하고 데이터 없는 톰스톤만 기록해야 합니다. 손상 JSON, 알 수 없는 스키마 및 멀티 탭 경합 변이에서 개인 raw 데이터가 남지 않는지 검증하십시오.

### I-10. 필수 CI 단계에 `if: false`를 붙이면 실제 검사를 건너뛰면서 workflow-check가 통과합니다

`Production dependency audit` 등 필수 검증 단계에 `if: false`를 추가한 변이에서 `release:workflow-check`가 통과했습니다. 문자열 기반 계약 검사는 단계 이름과 `run` 명령의 존재는 확인하지만, 해당 단계가 실제로 무조건 실행되는지는 확인하지 않습니다.

**영향:** 필수 보안 검사가 건너뛰어진 동일 SHA의 산출물이 업로드ㆍ배포될 수 있습니다.

**필수 조치:** YAML 구조를 파싱해 모든 필수 검증 단계에 `if`, `continue-on-error`, 실패 무시 셸 구문 또는 동등한 우회가 없음을 보장하십시오. 각 필수 단계를 `if: false`로 바꾸는 변이 테스트를 추가하고 업로드ㆍ배포가 그 단계들의 성공에만 의존하도록 검증하십시오.
